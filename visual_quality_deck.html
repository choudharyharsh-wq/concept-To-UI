Changing the Rendering Path
The largest source of visual-quality gains
3.1

Diagnosing the Figma-Plugin Path

✏️
Text written to the wrong field on components
✂️
Button labels clipped by auto-layout resize fights
📍
Flat absolute positioning instead of nested auto-layout — the biggest gap
🌗
Light screens rendered against a dark-by-default system
🧩
Components composed as isolated atoms, not patterns
107 component instances across 21 screens — DS adoption was healthy. The problem was the plumbing, not the model's decisions.

The Pivot: Deterministic HTML/CSS

Before
Model → wireframe → plugin translates → Figma properties
After

Removes property mis-mapping, resize fights, and variant-value rejections entirely. Now the primary rendering path.

Built, But Unfinished

The Review / Critique Loop

✅
"Design Head" PRD reviewer — scores the brief, asks clarifying questions
✅
Human-in-the-loop pause built into the pipeline graph
❌
IA, user-flow & layout evaluators — named "coming soon," never built
Every screen today is one-shot — no critique pass exists on the actual visual output.

Other Quality Levers

🚧
Category-Gating
Domain-specific components excluded when the brief doesn't mention that domain.
🖼️
Placeholder Imagery
On-theme icon + label instead of broken links or generic stock photos.
🗂️
Structured Output
Every stage forced into a validated schema — coordinates are always valid.
⚖️
Primitives + DS
Mostly basic elements; DS components only where they genuinely fit.

Known Gaps, In Our Own Words

📝
Pattern guidance is prose — never real working markup
🎯
No retrieval or targeting — full spec sent on every batch
🔁
No critique-and-refine pass — one shot per batch
👁️
Never shown a real finished screen — only written rules
